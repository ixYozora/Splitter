= Splitter

A *Minimal Viable Product (MVP)*, Splitter, is a simple tool that calculates the fair distribution of expenses among a group of people, ensuring that everyone pays their fair share based on the contributions they made during shared activities like trips or events.

The interface is in German. This guide gives the German labels as they appear on screen and explains
them in English.

== User Guide

=== Prerequisites

Docker, and nothing else. The application image is built from source inside Docker, so no JDK and no
Gradle installation are needed.

Everything except the documentation lives in the `splitter/` subdirectory. Run all commands from
there.

=== Step 1: Clone the repository

=== Step 2: Register a GitHub OAuth app

Signing in goes through GitHub, so the application needs its own OAuth app. Create one under
*Settings > Developer settings > OAuth Apps > New OAuth App* and fill out the form as follows:

* Your desired name for the project as the *Application name*.
* Use *http://localhost:9000* as the *Homepage URL*, as our application runs on port 9000.
* Optionally, provide a description.
* Use *http://localhost:9000* as the *Authorization callback URL*.

You should now receive the Client-ID and the Client-Secret. Copy these as you will need them in the
next step.

=== Step 3: Fill in the environment file

Copy the template and enter your values:

[source,bash]
----
cd splitter
cp .env.example .env
----

`.env` holds the Postgres database name, user and password, which you pick yourself, plus the
`GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` from step 2. That is all the application needs — the
`KEYCLOAK_*` block below stays empty unless you want the second sign-in provider from step 5. Git
ignores the file. Never commit it.

=== Step 4: Start it

`docker compose` reads `.env` by itself and waits for the database to be healthy before it starts
the application:

[source,bash]
----
docker compose build
docker compose up
----

The first command builds the application image from source and only has to be repeated after a code
change. Flyway applies the schema on startup, so there is nothing to import by hand.

The application then answers at *http://localhost:9000*. It is bound to the loopback interface, so
it is not published to your network.

=== Step 5: Sign in with Keycloak instead of GitHub (optional)

The compose file can bring a Keycloak up alongside the application, so you can sign in without a
GitHub account. It is a local development convenience and it is off by default.

Keycloak has to answer under the *same* address for your browser and for the application container,
otherwise the issuer in the token does not match the one the application asked for and the login
fails. Add the name to your hosts file once:

[source,bash]
----
echo "127.0.0.1 keycloak" | sudo tee -a /etc/hosts
----

Then fill in the `KEYCLOAK_*` values in `.env` — all of them are yours to choose — and set the two
switches sitting above them:

[source,properties]
----
COMPOSE_PROFILES=keycloak
SPRING_PROFILES_ACTIVE=keycloak
----

The first adds the Keycloak container to the stack, the second tells the application to offer it.
Empty them again to go back to GitHub alone. Start as in step 4: Keycloak reads
`splitter/keycloak/splitter-realm.json` on its first start and creates the realm, the client, and
the account named by `KEYCLOAK_DEV_USER` with the password next to it. That name is your identity
in the application, so it is also the name to add as a group member. The login page then offers
both providers, and the admin console is at *http://keycloak:8080*.

The realm is called *splitter* and that is not configurable: Keycloak takes the realm name from
the file name, so the two would have to change together.

The import only runs while the realm does not exist yet, so it never overwrites changes you make in
the admin console. To start over from the file, remove the volume:

[source,bash]
----
docker compose down
docker volume rm splitter_keycloak-data
----

The Keycloak client registration lives in `application-keycloak.yaml` and only loads under the
`keycloak` Spring profile. A plain `./gradlew bootRun`, the test suite and a compose run without
the two switches therefore stay on GitHub alone and need no Keycloak running.

== Guide to the Web Interface

=== Signing in

Opening the site offers you GitHub and, if you set it up in step 5, Keycloak. Once you authorise
the app you land on your group overview. Your user name at that provider is your identity in the
application, and group membership is matched on it, so members are added by that name and not as
free text.

The account menu at the top right shows who is signed in and holds *Abmelden* (sign out).

=== The overview page: "Deine Gruppen"

* The counter under the heading says how many of your groups are *offen* (open) and how many are
*geschlossen* (closed).

* To create a group, type a name into the input field and press *Anlegen*. Names are 5 to 30
characters long. You become the first member and land in the new group right away.

* Every row links to a group and shows its name, the number of members, its status and *Dein
Anteil*, your own net position in that group. A `+` means the others owe you, a `−` means you owe
them, and `0,00 €` means the group is even.

* *Dein Stand* below the list adds those positions up across all your groups.

* Once you have more than six groups, a search field and an *Alle / Offen / Geschlossen* filter
appear above the list. Both filter in the browser. Umlauts can be typed either way, so `Munchen`
finds `München` as well.

=== Inside a group

Members are on the left, the expense form and the receipts on the right, the settlement across the
bottom.

==== Members: "Mitglieder"

Enter a user name under *Mitglied hinzufügen* and press *Hinzufügen* — the name the member signs in
with at GitHub or Keycloak. Members appear below as tokens carrying their initial, and your own
carries the mark *du*. Once a group has more than six members the list folds up and *+x weitere*
expands it. A closed group always shows everyone.

Members can be added only while the group has no expenses. The first recorded expense fixes the
roster.

==== Recording an expense: "Ausgabe erfassen"

* *Aktivität* is what the money was spent on, for example `Pizza`.

* *Ausleger* (who paid) and *Teilnehmer* (who took part) are filled by moving member tokens into the
two zones below. Drag a token across, or activate it once to pick it up and activate the zone to put
it down. The second way also works from the keyboard. *Ausleger* takes one person, *Teilnehmer*
takes as many as you want, and the small × on a token removes it again.

* *Betrag* is the amount, written as `12,50` or as `12.50`. As soon as an amount and one participant
are set, the share per person appears under the *Teilnehmer* zone and updates as you type.

* *Erfassen* records the expense. The payer does not have to be one of the participants. If they are
not, they fronted the cost for the others.

Without JavaScript the two zones are replaced by a dropdown for the payer and a text field for the
participants, separated by a comma and a space, for example `MaxHub, GitLisa`.

==== Receipts: "Kassenbons"

Each recorded expense becomes a receipt with the activity, the date, who fronted the cost, the share
per participant and the total. The six most recent ones stand on the page, and *+x weitere* opens a
dialog with all of them. Escape, the × or a click next to the dialog closes it.

==== Settlement: "Ausgleich"

*Ausgleich berechnen* works out who pays whom. The result is drawn as a diagram of arrows between
the members, and *Als Liste anzeigen* switches to the same information as a list of `A zahlt X € an
B` lines.

The result uses the smallest possible number of transfers, nobody pays and receives at the same
time, and no two people transfer money in both directions. Record further expenses and press the
button again for an updated result.

If the expenses already balance, the section says so instead of listing transfers.

==== Closing a group: "Gruppe schließen"

*Gruppe schließen* locks the group. No further members, no further expenses, no recalculation.
Receipts and settlement stay readable, including the dialog with all receipts.

Closed groups keep showing up on the overview under the *Geschlossen* filter.
